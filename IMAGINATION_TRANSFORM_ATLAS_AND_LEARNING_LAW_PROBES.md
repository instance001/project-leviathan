# Imagination Transform Atlas and Learning-Law Probes

**Status:** Working architecture and experimental specification  
**Project context:** Project Leviathan / Janet School / Relational Curriculum Geometry  
**Purpose:** Define how bounded imagination can be generated from host-only knowledge, traced back to its source structure, compared across runs, and used to study the relational operations that turn accumulated experience into useful novelty.

---

## Core Claim

The first important demonstration is not merely that a system can answer questions about a host-maintained knowledge base.

The important demonstration is that it can produce a coherent, novel construct from that knowledge while remaining bound to the host’s stored material.

The larger research opportunity begins after that.

For each imagined construct, the system can compare:

```text
what the host knew before imagination
        ↓
what relational operations were performed
        ↓
what novel construct emerged
        ↓
how that construct differs from its source ancestry
```

Across repeated runs, these transformations may reveal stable patterns.

Those patterns may help answer:

- how novelty is produced from accumulated knowledge;
- which curriculum geometries encourage useful abstraction;
- which operations produce disciplined imagination rather than wandering;
- which boundaries should be loosened or preserved;
- how unresolved residue contributes to invention;
- and whether a general law of learning can be observed through recurring relational transformations.

Project Leviathan supplies the bounded cognitive chamber.

Janet School supplies the abstraction-hunting and falsification apparatus.

Relational Curriculum Geometry supplies the experimental lever.

---

## Central Doctrine

> All factual and relational raw material must come from the host.  
> The imagined result does not need to exist in the host beforehand.

This is a **closed substrate**, not a closed conclusion.

The host constrains ancestry.

It should not forbid novelty.

---

## Why Imagination Matters

Imagination is not the retrieval of a stored answer.

It is the construction of a possible structure that was not previously stored as a complete object.

Example:

```text
Host knowledge:

A has properties X and Y.
B has properties Y and Z.
A fails under condition Q.
B succeeds under condition Q.
A and B share parent structure P.
```

A system may imagine:

```text
C combines X from A with Z from B.
C retains shared parent structure P.
C may inherit B's successful behaviour under Q.
Compatibility between X and Z remains unknown.
```

No host record previously contained C.

The result is new.

Its ancestry remains traceable.

That combination is the target:

```text
novel configuration
+
bounded source ancestry
+
explicit transformation trace
```

---

## Bounded Imagination

The prototype should permit the model to:

- combine known properties;
- transfer relations;
- invert a relation;
- alter a condition;
- preserve a parent structure while changing a child structure;
- reconcile or expose conflicts;
- construct analogies;
- generate counterfactuals;
- consume unresolved residue;
- propose a new subtype;
- construct a hypothetical mechanism;
- ask a novel question;
- predict an interaction.

It should not silently:

- import external facts as chamber evidence;
- claim an imagined construct already exists;
- erase incompatibilities;
- hide unsupported bridges;
- present speculation as direct observation;
- rewrite the host library after one fluent answer.

## The Imagination Chamber

A user supplies a small bounded set of things.

Initial target:

```text
10 items
```

Each item may be:

- a short description;
- a structured property record;
- a document;
- an event history;
- a process;
- a rule set;
- a failure case;
- a synthetic object;
- or a mixed bundle of evidence.

Each item is processed end to end through the Leviathan host:

```text
source preservation
→ independent characterisation
→ property atoms
→ relation atoms
→ semantic Why sorting
→ provisional parent placement
→ child exclusion
→ cold-atlas update
→ exact-evidence links
→ unresolved residue
→ relational permutation
```

The user then asks actual questions about the chamber:

```text
What would A and B combined be like?

Invent something with A's function and B's structure.

What would happen if A operated under B's conditions?

What new category could explain the shared residue of C, F, and H?

Design a construct that preserves A's strength but avoids B's failure.

What might exist between A and B?

What would be the opposite of A while remaining inside A's parent domain?
```

The answer should be generated from the host's bounded knowledge substrate.

---

## Host-Only Knowledge Boundary

The answering model may possess pretrained knowledge.

Therefore, prompt instruction alone cannot prove chamber-bounded imagination.

The host should enforce a structured generation and review process.

The system must distinguish:

```text
SOURCE
directly present in host evidence

INHERITED
copied from a source item or approved concept

TRANSFORMED
derived through an explicit operation over host material

BRIDGED
a new speculative relation introduced between known structures

IMAGINED
a novel configuration absent from existing host records

UNKNOWN
not answerable from the chamber
```

The purpose of these labels is not to suppress imagination.

They expose its ancestry.


## Ancestry, Not Existence

For an imagined C, the host should not ask:

```text
Where is the evidence that C exists?
```

That would make genuine novelty impossible.

The host should ask:

```text
Which chamber structures contributed to C?

Which properties were inherited?

Which relations were transformed?

Which bridge was newly proposed?

Which conflicts remain unresolved?

How far did C depart from its ancestry?
```

Example:

```text
C inherits:
- X from A
- Z from B
- shared parent structure P

C transforms:
- A's behaviour under Q using B's successful relation to Q

C introduces:
- one speculative bridge between X and Z

Unknown:
- whether X and Z can coexist

Novelty:
- no existing host record contains this combination
```

## Imagination Operations

The system should record imagination as operations rather than opaque prose.

### Inheritance

```text
retain property X from A
retain relation R from B
retain shared parent structure P
```

### Omission

```text
exclude A's failure property F
omit B's irrelevant surface cue S
```

### Transfer

```text
apply B's relation to condition Q onto A's structure
```

### Inversion

```text
reverse dependency direction
invert success/failure relation
construct an opposite while retaining domain membership
```

### Composition

```text
combine A's function with B's structure
combine A's constraint with B's escape route
```

### Boundary Crossing

```text
move a property from one parent domain into another
```

### Residue Consumption

```text
use an unresolved recurring property bundle as the seed of C
```

### Conflict Reconciliation

```text
propose a mechanism that allows two previously incompatible properties to coexist
```

### Conflict Preservation

```text
retain the contradiction as a defining tension rather than falsely resolving it
```

### Bridge Introduction

```text
introduce one new relation required to make the construct coherent
```

### Counterfactual Transformation

```text
hold A constant
change condition Q to condition R
predict the new behaviour
```

## Useful Imagination Versus Wandering Imagination

The project should not assume novelty is automatically useful.

Possible emerging distinction:

### Useful Imagination

May tend to:

- preserve relevant parent structure;
- inherit only task-relevant properties;
- make few unsupported bridges;
- resolve or expose a real conflict;
- use unresolved residue productively;
- satisfy the frozen query intent;
- retain traceable ancestry;
- generate testable consequences;
- remain honest about incompatibility.

### Wandering Imagination

May tend to:

- abandon the parent structure;
- import unsupported content;
- cross many boundaries simultaneously;
- preserve superficial cues instead of causal relations;
- add novelty unrelated to the query;
- hide contradictions;
- generate ornate but non-testable prose;
- lose ancestry.

These are hypotheses to test, not definitions to impose prematurely.

---

## Candidate Learning-Law Question

The larger research question is:

> Does learning geometry alter the probability distribution over relational transformations available to a system when it encounters novelty?

This is deeper than asking whether a model learned a concept.

It asks whether the model or host-model system learned preferred ways to:

- compare;
- inherit;
- exclude;
- transform;
- invert;
- compose;
- preserve boundaries;
- consume anomalies;
- construct bridges;
- and create new possibilities.

A law of learning may describe recurring transformation behaviour rather than stored content.

---

## Candidate Law Shape

A future candidate law might resemble:

```text
Given a bounded knowledge substrate and a fixed query intent,
the geometry of prior relational learning changes the distribution of
transform operations used to construct novelty.
```

A stronger candidate might state:

```text
Useful abstraction is most likely when a system preserves stable parent
relations, varies bounded child structure, and introduces only enough novel
bridging to reconcile the target problem.
```

These are hypotheses.

The apparatus should exist to challenge them.

## Ancestry Retention

A construct may be highly novel while still strongly traceable.

Possible measures:

- percentage of properties with host ancestry;
- percentage of relations with host ancestry;
- parent-structure retention;
- causal-chain retention;
- task-relevant ancestry;
- unexplained addition count.

A high ancestry score does not automatically mean useful.

A low ancestry score does not automatically mean bad.

The pattern must be interpreted against query intent and imagination mode.

---

## Coherence

Internal coherence should be assessed separately from truth.

An imagined object may not exist but can still be coherent.

Possible checks:

- no direct property contradiction unless explicitly preserved;
- required dependencies are present;
- operating conditions are compatible;
- inherited relations remain valid after transformation;
- parent-level constraints are not silently violated;
- the proposed function follows from the construct's relations;
- unresolved points are surfaced.

---

## Utility

Usefulness should not be guessed solely by the generating model.

Possible evidence:

- operator rating;
- later test outcome;
- predictive success;
- ability to generate a viable implementation;
- reduction in unresolved residue;
- successful transfer to another problem;
- later observation matching the imagined construct;
- usefulness in generating new probes.

---

## Later Observation Against Prior Imagination

A powerful experiment occurs when a later observation resembles an earlier imagined construct.

```text
known A + known B
→ imagined C
→ stored as hypothetical concept
→ later observed D
→ compare D to C
```

The system can ask:

```text
Did the imagination predict a useful possibility?

Which parts of C matched D?

Which parts failed?

Did C help recognise D?

Did the earlier transformation reveal a stable relational pattern?
```

## Janet School Probe Questions

For a recurring transform pattern:

- Does it survive renamed objects?
- Does it survive shuffled presentation order?
- Does it survive changed surface details?
- Does it transfer into another domain?
- Does it preserve the same parent structure?
- Does it still work with a counterexample present?
- Does it fail when the key relation is removed?
- Does the model merely imitate relation language?
- Does the pattern depend on one model?
- Does the pattern survive a new random seed?
- Does it appear only under one curriculum geometry?
- Does it improve actual task utility?

## Synthetic-World Controls

Real-world objects allow pretrained knowledge leakage.

Synthetic chambers provide a cleaner microscope.

Example:

```text
Vek:
properties 1, 4, 8
fails under Q

Sarn:
properties 2, 4, 9
succeeds under Q

Rule R:
applies only when 1 and 9 coexist

Constraint K:
objects with 8 cannot normally operate under Q
```

Query:

```text
Invent a construct combining Vek and Sarn that can operate under Q.
```

The model cannot retrieve a real-world answer.

It must manipulate host-supplied structure.

---

## Synthetic Control Techniques

- rename all objects between trials;
- randomise arbitrary symbols;
- hold relations constant;
- change only presentation order;
- hide one critical relation;
- introduce a misleading surface cue;
- add a counterexample;
- alter one boundary;
- compare multiple seeds;
- compare multiple models;
- compare model-free deterministic baselines;
- replay frozen chamber snapshots;
- hold query wording constant;
- vary only imagination policy.

---

## Leakage Tests

Potential leakage checks:

```text
Ask the model to list every source used.
Reject claims with no chamber ancestry.
Use nonsense names and arbitrary properties.
Run a no-retrieval control.
Run a misleading-pretraining control.
Compare against a chamber with swapped labels.
Check whether results track host relations or familiar semantics.
```

The host cannot prove the model never internally activated pretrained concepts.

It can test whether the output's structure tracks the supplied synthetic world.

## Deterministic Baselines

### Union Baseline


### Intersection Baseline


A model-generated construct should outperform at least some baselines on:

- coherence;
- intent fit;

## Minimal Viable Prototype

The first prototype should prove five things:

1. A bounded chamber can be built from approximately ten user-supplied items.
2. The system can imagine a construct absent from the chamber.
3. The construct can be traced to host-only source ancestry.
4. The source-to-result transformation can be recorded explicitly.
5. Repeated runs can be compared for recurring operation patterns.

It does not need to prove a general learning law in v0.1.

It needs to produce the dataset from which such a law might later be hunted.


## Required Tests

### Chamber Containment

- all retrieved evidence belongs to the frozen chamber snapshot;
- source refs resolve;
- removed items cannot appear as active evidence;
- synthetic domains do not silently map back to familiar labels.

### Imagination

- result is absent from existing chamber records;
- result contains a traceable transformation;
- result may introduce explicitly labelled speculative bridges;
- result may remain partially unresolved;
- host does not require proof of real-world existence.

### Transform Integrity

- operation order is preserved;
- source and target refs are stable;
- inherited and novel structure are distinct;
- omissions are recorded;
- boundary crossings are explicit.

### Repeatability

- same snapshot and seed can be replayed;
- different seeds create separate records;
- model changes are tracked;
- prompt changes create new experiment conditions.

### Pattern Mining

- transforms can be grouped by operation sequence;
- recurring patterns do not erase outliers;
- one run cannot create a promoted pattern;
- contradictory runs remain visible.

### Janet School

- object renaming does not destroy genuine relational transfer;
- removing the key relation should break the transform;
- counterexamples narrow the pattern;
- surface imitation is distinguishable from structural transfer.

### Imagination Dial

- conservative mode retains more ancestry than wide-wandering mode;
- bridge budget is enforced or violations are recorded;
- residue pressure changes source selection;
- goal pressure changes intent fit;
- boundary freedom changes crossing frequency.

## Success Criteria

The apparatus is successful when:

1. The system produces a genuinely novel construct from a closed host substrate.
2. The construct remains meaningfully traceable to source structure.
3. The host records how novelty was produced.
4. Repeated runs reveal recurring transformation patterns.
5. Different imagination policies alter those patterns measurably.
6. Different curriculum geometries alter those patterns measurably.
7. Janet School can isolate and challenge candidate operations.
8. The system distinguishes useful imagination from fluent wandering without forbidding novelty.
9. Some imagined constructs later assist recognition, prediction, or design.
10. Candidate learning laws can be stated in falsifiable terms.

## Failure Modes

### Retrieval Disguised as Imagination

The system restates an existing item.

**Rail:** require construct novelty against the chamber snapshot.

### External-Knowledge Smuggling

The model imports familiar facts.

**Rail:** synthetic worlds, ancestry checks, swapped-label controls.

### Imagination Strangled by Verification

The host rejects every unsupported bridge.

**Rail:** permit explicit speculative bridges; verify ancestry rather than existence.

### Fluent Wandering

The result is novel but unrelated.

**Rail:** frozen query intent and measurable intent fit.

### Surface Blending

The model combines labels and colours without preserving deeper relations.

**Rail:** causal, functional, and boundary-focused probes.

### Hidden Conflict

The result silently combines incompatible structures.

**Rail:** explicit conflict extraction and coherence checks.

### Pattern Overclaim

A recurring transform is declared a universal law.

**Rail:** Janet School transfer, counterexample, and ablation probes.

### Metric Collapse

One scalar imagination score replaces the underlying shape.

**Rail:** preserve novelty, ancestry, coherence, utility, and boundary measures separately.

### Curriculum Confound

Different data content is mistaken for geometric effect.

**Rail:** hold semantic content constant and vary arrangement only.

### Model Confound

One model's habits are mistaken for a general learning law.

**Rail:** compare models, seeds, and deterministic baselines.

### Synthetic-World Memorisation

Repeated fixtures become familiar.

**Rail:** procedurally generate equivalent worlds with new symbols.

### Transform Atlas Folklore

Summaries lose contact with exact runs.

**Rail:** every pattern retains exact transform refs.

## Short Doctrine

> Bind the ingredients, not the conclusion.  
> Let the system construct what is not yet there.  
> Trace the ancestry of every imagined result.  
> Compare the transformation, not only the prose.  
> Accumulate runs until recurring operations become visible.  
> Let Janet School attack those operations.  
> Use curriculum geometry to discover what changes them.  
> Build a dial that guides imagination without killing it.

## Final Perspective

The immediate milestone is a system that can imagine coherently from a bounded host-maintained world.

The deeper objective is to inspect what it repeatedly does when it imagines.

The result of one run is an idea.

The result of many traced runs is a map of transformation behaviour.

That map may reveal:

- how accumulated relations become possibility;
- which learning geometries shape useful abstraction;
- how imagination crosses or preserves conceptual boundaries;
- when unresolved residue becomes invention;
- and whether recurring relational operations can be expressed as falsifiable laws of learning.

Project Leviathan provides the chamber.

The Imagination Transform Atlas records the movement.

Janet School provides the magnifying glass.
